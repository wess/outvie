Features

Your library, your hardware, any screen.

Everything you need to run a household retro arcade — without a microservice graveyard.

🌐

All-WASM by default

No plugins, no native installs. Open the URL and play in any modern browser via WASM libretro.

🦀

Streaming-ready engine

A Rust libretro frontend ships in the image. Drop in cores to stream server-side rendering over WebSockets.

💾

Per-user saves

Save states live in a per-user folder, so each player's checkpoints stay separate and private.

🎮

Controller-aware

The standard gamepad layout works out of the box, and the HUD shows exactly what's plugged in.

🔐

Your own SSO

OIDC relying-party via @atlas/sso gates everything. Visitors can play; only your account manages the library.

📦

One container, one Postgres

A single Docker image plus Postgres. ROMs on disk, metadata in the database — no service sprawl.

🗂️

Bulk ROM import

Seed a fresh library from a folder: sha1-dedupe, sniff the system from header bytes, ~2.5s for 1,500 ROMs.

⬇️

Ranged ROM delivery

ROM bytes stream with range support and token-scoped access, so the browser fetches only what it needs.

🏠

Homelab-native

Built to deploy on castle/vegeta: Postgres provisioning, nginx vhosts, and OAuth client minting.

Architecture

A Bun API, Postgres, and ROMs on disk.

  • ✦Mantine SPA — React 19 + nostalgist runs WASM libretro in the browser, with the Web Gamepad API mapped to libretro inputs.
  • ✦Bun API — games CRUD, ranged ROM delivery, per-user saves, and a WebSocket stream proxy, all behind JWT.
  • ✦Postgres + disk — only metadata lives in Postgres; ROMs sit at data/roms/<system>/<id> and saves are per-user.
  • ✦Optional Rust engine — a libretro frontend streams WebM video over WebSockets when cores are installed.
  • ✦SSO via Atlas — @atlas/auth JWTs and @atlas/sso OIDC; Castle is the IdP in the homelab setup.

Get started

Up and running with Docker.

Clone, copy the env file, and bring it up with Compose. The first user to sign in becomes the owner.

terminal 
# 1. clone
git clone https://github.com/wess/outvie && cd outvie

# 2. configure
cp env.example .env

# 3. run
docker compose up -d
open http://localhost:4290   # first sign-in = owner

Prefer to hack on it locally? Run the API and SPA from source.

local dev 
# install deps + a throwaway Postgres
bun install
docker run -d --name pg -p 5432:5432 -e POSTGRES_PASSWORD=postgres postgres:16-alpine
docker exec -i pg psql -U postgres -c "CREATE DATABASE outvie;"

# run the API on :4290 and the SPA on :5174
bun run dev:server
bun run dev:web
